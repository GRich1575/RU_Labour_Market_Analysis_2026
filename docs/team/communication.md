# Коммуникация в команде: каналы, поддержка, проверка данных

> **СТАТУС: ПРЕДЛОЖЕНИЕ (не включено).** Решение о каналах и правилах — после консультаций с командой. Связано с `docs/team/README.md` (командная политика отключена) и с блокером этапа 1 (облачное хранилище, `PROGRESS.md` п. 12–13).

Цель: быстро получать помощь, не терять файлы и не отправлять данные и секреты в неподходящие места.

## 1. Какие каналы нужны
| Задача | Где | Почему |
|---|---|---|
| Вопрос «как сделать» (быстрый) | мессенджер-группа | быстрый ответ, без оформления |
| Ошибка в коде, задача, проверка источника | GitHub Issues | история, ссылки на файлы, можно закрыть |
| Проверка исходного файла данных | GitHub Issue + карточка файла (см. п. 4) | воспроизводимость |
| Передача исходных файлов (XLSX, PDF, SAV) | облачное хранилище с ограниченным доступом | не в чат и не в git |
| Образец (≤200 строк, ≤1 МБ) | мессенджер или PR в `data/samples/` | для обсуждения |
| Решения | `PROGRESS.md` (через PR или координатором) | единый источник правды |

Правило: **решение, принятое в чате, переносится в `PROGRESS.md` или в Issue в тот же день.**

## 2. Мессенджер: Telegram или WhatsApp
| Критерий | Telegram | WhatsApp |
|---|---|---|
| Шифрование групповых чатов | по умолчанию не сквозное (в «секретных чатах» — да, только 1:1) | сквозное по умолчанию (включая группы) |
| Лимит файла | до 2 ГБ | до 2 ГБ (документы) |
| Удаление сообщений | можно у всех в группе | только у себя или «удалить для всех» в течение времени |
| Рекомендация | если нужны боты/поиск по чату; не отправлять туда ключи и персональные данные | если важна конфиденциальность; подходит для вопросов и образцов |

Рекомендация: **WhatsApp** для вопросов и образцов (сквозное шифрование), если все участники им пользуются. Решение — команде.

## 3. Правила для чата
- В чат: вопросы, скриншоты без персональных данных, образцы (≤200 строк, ≤1 МБ, без персональных полей).
- Не в чат: исходные файлы из `data/raw/`, ключи API, пароли, токены, логины GitHub с паролями, полные контакты респондентов.
- Перед отправкой скриншота или файла — проверить, нет ли в нём ФИО, телефонов, e-mail, идентификаторов.
- Ответ на вопрос из чата, который повторяется, — перенести в `docs/`.
- Не отвечать на просьбы «пришлите токен» или «установите программу по ссылке» от незнакомых; подтверждать через координатора.

## 4. Карточка файла (для проверки и поддержки)
Прикладывается к Issue или сообщению при передаче файла:
```
Файл:           <имя по naming_and_formats.md>
Источник:       <source_id>
Откуда:         <точный URL>
Дата загрузки:  YYYY-MM-DD
Период данных:  <покрытие, например 2026-01to2026-09>
sha256:         <хеш>
Размер:         <байт>
Кто загрузил:   <участник>
Проблема:       <что не так, текст ошибки целиком>
Что уже пробовали: <шаги>
```
Команды для хеша:
- Windows: `certutil -hashfile <файл> SHA256`
- macOS/Linux: `shasum -a 256 <файл>` (или `sha256sum <файл>`)

## 5. Поддержка: как просить и отвечать
1. Сначала — поиск в `docs/` и `PROGRESS.md` (возможно, ответ уже есть).
2. Вопрос — короткое сообщение в чат или Issue с шаблоном (п. 4 или описание ошибки).
3. Ошибка — полный текст, команда, версия Python (`python --version`), ОС.
4. Ответ — в том же канале; решение фиксируется (п. 1).
5. Цель ответа: первый отклик в течение 1 рабочего дня (предложение).

## 6. Проверка данных
Процедура для любого нового исходного файла:
1. Владелец источника добавляет файл в облако и заполняет карточку (п. 4).
2. Координатор (или второй участник) проверяет: период совпадает с `2026`; источник и URL соответствуют `config/sources.yaml`; хеш совпадает у обоих; кодировка и разделитель описаны.
3. Результат записывается в `PROGRESS.md` или в Issue: «проверено / отклонено / нужна правка» с датой.
4. Только после «проверено» источник получает `enabled: true` (через PR, если командная политика включена).
5. Отклонённый файл не удаляется: статус `rejected` в карточке.

## 7. Безопасность аккаунтов и доступов
- Включить двухфакторную аутентификацию на GitHub и в облачном хранилище.
- Доступ к облаку — по ссылке с ограниченным доступом (только участники), а не «всем, у кого есть ссылка».
- Токены GitHub — с минимальными правами и сроком действия; не вставлять в чат и в файлы.
- Координатор удаляет доступ участника, который вышел из проекта.
- Публичный репозиторий: не публиковать образцы с персональными данными; проверить приватность (см. `docs/team/collaboration.md`).
