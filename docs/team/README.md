# Командная работа — статус: ОТКЛЮЧЕНО

Документы в этой папке — черновик политики для совместной работы. Политика не применяется. Решение о включении принимается позже: навыки студентов могут не позволить использовать полный набор правил.

## Что есть
- `collaboration.md` — роли, защита `main`, PR, ветки, хранение данных, чек-лист PR.
- `naming_and_formats.md` — шаблоны имён файлов, манифест, кодировки, даты.

## Что сейчас не действует
- Обязательные PR и защита `main`.
- Ветки `stage<N>/<member_id>-<тема>`.
- Манифест `data/MANIFEST.csv` (файл не создан).
- Папка `data/samples/` (не создана).
- Облачное хранилище для `data/raw/` (не выбрано).
- Правила `.gitattributes` и дополнительные строки `.gitignore` (не добавлены).

## Как включать (по частям, от простого к сложному)
Включать можно поэтапно; каждый уровень — отдельное решение команды.
1. **Уровень 1 — имена и форматы.** Кодировка UTF-8, `;` в CSV, даты `YYYY-MM`, `YYYY-Qn`. Проверяется глазами.
2. **Уровень 2 — манифест.** `data/MANIFEST.csv` с sha256 для каждого исходного файла. Требует умения считать хеш (`certutil` / `sha256sum`).
3. **Уровень 3 — ветки и PR.** Ветки по этапам, PR в `main`, ревью. Требует навыков git; рекомендуется только при наличии участника, который может вести git.
4. **Уровень 4 — защита `main` на GitHub.** Настройки владельца репозитория; включать только вместе с уровнем 3.

## Связанные решения
- **Облачное хранилище для `data/raw/`** — не выбрано. Будет решено после консультаций с командой. Это блокер завершения этапа 1 (см. `docs/stage1/brief.md`, `PROGRESS.md` п. 12).
- **Группа в мессенджере** (Telegram или WhatsApp) — опция для вопросов, координации и загрузки образцов. Правила, если включена:
  - В чат — только усечённые образцы (≤200 строк, ≤1 МБ), без персональных данных и ключей API.
  - Исходные файлы из `data/raw/` в чат не загружать.
  - Итоговые образцы попадают в репозиторий через PR, а не через чат.
  - Решения, зафиксированные в чате, переносятся в `PROGRESS.md` или issue.

## Условия для решения
- Кто в команде знаком с git (ветки, merge, конфликты)?
- Есть ли один человек, который готов отвечать за merge и защиту `main`?
- Где хранятся исходные данные (облако) и кто ведёт их?
- Репозиторий приватный или публичный?

Решение записывается в `PROGRESS.md` (раздел «Открытые вопросы»).
