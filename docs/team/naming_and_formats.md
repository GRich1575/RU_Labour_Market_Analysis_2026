# Единый формат и правила имён

> **СТАТУС: ОТКЛЮЧЕНО (черновик, не применяется).** Включается по решению команды; см. `docs/team/README.md`. Пока файлы в проекте называются по текущей практике, без обязательного шаблона.

Действует для всей команды, после включения. Любой файл, не соответствующий правилам, не принимается в PR.

## 1. Общие правила
- Имена файлов и папок: строчные латинские буквы, цифры, `_` и `-`. Без пробелов, кириллицы, скобок и `#`.
- Исключение: русскоязычные документы в `docs/` — имя в латинице (`brief.md`, `issues.md`), текст — на русском.
- Дата в имени — `YYYYMMDD` (дата загрузки) или `YYYY-MM` (период). Никогда `DD.MM.YYYY` в имени.
- Версия — `_v1`, `_v2` … Не использовать `final`, `new`, `копия`, `окончательный`.
- Один файл — одна задача. Не переименовывать чужие файлы; новая версия — новый файл.

## 2. Идентификаторы источников
- `source_id` — из `config/sources.yaml` (например `rosstat_orc`, `cbr_key_rate`). Не менять без PR.
- Папка сырых данных: `data/raw/<source_id>/`. Папка образцов: `data/samples/<source_id>/`.

## 3. Исходные файлы (`data/raw/<source_id>/`)
Шаблон имени:
```
<source_id>_<YYYYMMDD>_<период>_v<N>.<ext>
```
- `YYYYMMDD` — дата загрузки.
- `<период>` — покрытие данных: `2026` (год), `2026-Q1` (квартал), `2026-01` (месяц), `2026-01to2026-09` (диапазон).
- `<ext>`: `xlsx`, `xls`, `csv`, `pdf`, `html`, `json`, `xml`, `sav`, `dta`, `docx`.

Пример: `cbr_key_rate_20261117_2026-01to2026-11_v1.html`

Исходное имя файла (как скачан) — в `README.txt` папки (поля ниже) и в `data/MANIFEST.csv`.

### README.txt в папке источника
```
Источник: <source_id> — <название>
Адрес: <точный URL страницы/файла>
Дата загрузки: YYYY-MM-DD
Исходное имя файла: <как было>
Период данных: <покрытие>
Таблица/показатель: <название, ID в ЕМИСС если есть>
Загрузил: <member_id>
Кодировка и разделитель: <как в файле>
Проверка: <что проверено, результат>
```

## 4. Манифест (`data/MANIFEST.csv`)
Git хранит манифест; сами файлы — в облачной папке.
Колонки (в этом порядке):
```
file,source_id,period,sha256,size_bytes,downloaded_on,origin_url,member_id,status,notes
```
- `file` — имя из п. 3.
- `sha256` — контрольная сумма файла (нижний регистр).
- `status`: `active` (актуальная версия), `superseded` (заменена новой), `rejected` (не подходит).
- Одна строка на файл. Старые версии не удаляются из манифеста.

## 5. Образцы (`data/samples/<source_id>/`)
- Формат: CSV, UTF-8, разделитель `;`, десятичный знак — `,` (см. п. 7).
- Размер: ≤200 строк данных, ≤1 МБ.
- Имя: `<source_id>_sample_<период>.csv`, например `cbr_key_rate_sample_2026.csv`.
- Образец — результат кода или явного шага, описанного в `README.txt`. Ручная правка образца запрещена.

## 6. Обработанные таблицы (`data/processed/`)
- Создаются скриптами; вручную не редактируются. Не коммитятся в git.
- Имя: `<показатель>_<география>_<частота>_<год>.csv`
  - показатель: `unemployment`, `key_rate`, `cpi`, `vacancies` (латиница, snake_case);
  - география: `rf`, `fo_<код>` (федеральный округ), `reg_<код>` (регион, код из `data/reference/`);
  - частота: `daily`, `monthly`, `quarterly`, `annual`;
  - год: `2026`.
- Пример: `key_rate_rf_daily_2026.csv`, `unemployment_rf_monthly_2026.csv`.
- Стандартная длинная форма (колонки строго в этом порядке):
```
дата;регион;показатель;значение;единица;источник
2026-01-05;РФ;ключевая ставка;16,00;%;cbr_key_rate
```
- Имя колонок — русские, как в примере; `источник` — `source_id`.

## 7. Кодировка, разделители, числа, даты
| Параметр | Правило |
|---|---|
| Кодировка | UTF-8 (без BOM) для всех CSV, JSON, Markdown |
| Разделитель CSV | `;` |
| Десятичный знак в CSV | `,` (русская локаль, Excel) — **предложение, ждёт решения преподавателя** |
| Тысячи | без разделителя (`1234567`, не `1 234 567`) |
| Пропуски | пустая ячейка; не `-`, не `n/a`, не `0` |
| Даты (месяц) | `YYYY-MM` |
| Даты (день) | `YYYY-MM-DD` |
| Кварталы | `YYYY-Qn` (`2026-Q1`) — заменяет `ГГГГ-КК` из `data/README.md` |
| Проценты | в колонке `единица` — `%`; значение 16,00 (не 0,16) |
| Пути в тексте | относительные от корня репозитория, `/` |

## 8. Код, документы, ветки
- Python-модули и функции: `snake_case` (`load_cbr_key_rate.py`); тесты: `test_<модуль>.py` в `tests/`.
- Документы этапа: `docs/<stage>/brief.md`, `issues.md`, `source_checks.md`.
- Ветки: `stage<N>/<member_id>-<тема>`. Коммиты: `stage<N>: <что сделано>`.

## 9. Что запрещено
- Файлы с именами `копия`, `final`, `новый`, `tmp`, `test2`.
- Исходные данные вне `data/raw/` и облачной папки.
- Два файла с одинаковой контрольной суммой под разными именами без записи в манифесте.
- Правка исходного файла с сохранением на месте.
