# Учёт трудностей и помощь команде (анонимно)

> **СТАТУС: ПРЕДЛОЖЕНИЕ (не включено).** Включение — после решения команды (см. `docs/team/README.md`). Связано с `docs/team/communication.md` и `docs/team/automation_design.md`.

Цель: видеть, где команда застревает, и быстро помогать — без оценки отдельных людей, без рейтингов и без слежки за активностью. Участник не называет себя. Координатор видит только сводку.

## 1. Принципы
- **Анонимность по умолчанию.** Опросы и формы не собирают имя, e-mail, логин GitHub или номер группы.
- **Нет рейтингов.** Нигде не сравниваются «активные» и «неактивные» участники.
- **Нет слежки.** Не отслеживаются клоны, коммиты и время работы по людям.
- **Помощь, а не контроль.** Цель каждого сбора — изменить документы, инструкции и поддержку.
- **Добровольность.** Заполнение необязательно; пропуск не влияет ни на что.
- **Минимум данных.** Записывается только то, что нужно для помощи.

## 2. Что важно знать про анонимность
- **GitHub Issues не анонимны**: автор виден координатору. Поэтому для трудностей используется отдельная анонимная форма, а не Issues.
- **Команда маленькая.** Даже без имени можно угадать автора по редкой комбинации ответов. Защита: сводка показывается только если ответов не меньше 3 (п. 6), а свободный текст публикуется только после очистки от имён.
- **Выбор платформы формы** (решение команды): Google Forms или Microsoft Forms, с отключённым сбором e-mail и без входа в аккаунт. Владелец формы видит ответы, но не личность отвечающего, если сбор e-mail выключен. Это надо проверить в настройках выбранного сервиса перед запуском.

## 3. Форма трудностей (еженедельно или по мере необходимости)
Поля (все необязательные, кроме первых двух):

| Поле | Тип | Значения |
|---|---|---|
| Этап | выбор | 1 … 7 |
| Тип трудности | выбор | блокер (не могу продолжить) / данные не найдены / установка и окружение / непонятно, что делать / ошибка в документе / другое |
| Источник (если касается) | выбор | id из `config/sources.yaml` / не касается / другое |
| Что пробовал | текст, до 300 символов | свободный текст |
| Нужна помощь | выбор | да / нет |
| Насколько понятна инструкция | шкала | 1–5 |

Не просить: имя, фамилию, группу, e-mail, логин, номер телефона, фото документов.

## 4. Чекпоинт этапа (раз в этап)
Один вопрос: «Этап закрыт / частично / блокер». Плюс поле «что помогло бы» (текст). Без идентификаторов.

## 5. Как реагируем на трудности
1. Координатор раз в неделю смотрит сводку (п. 6).
2. Частые трудности (≥3 ответа) → исправление: уточнить инструкцию в `docs/`, добавить запись в FAQ.
3. Одиночные трудности с текстом → ответ в общем канале без указания, кто спрашивал: «Есть вопрос, как…».
4. Блокеры по источнику → строка в `PROGRESS.md` («Открытые вопросы») и, если нужно, обновление `docs/stage1/brief.md`.
5. Изменения в FAQ фиксируются коммитом с префиксом `docs:` (см. `docs/team/naming_and_formats.md`).

FAQ — файл `docs/FAQ.md`. Создаётся при включении процесса; каждая запись — вопрос, короткий ответ, ссылка на документ.

## 6. Что показывает сводка (дашборд)
- Количество ответов по типу трудности и по этапу.
- Топ-3 источника с трудностями.
- Средняя понятность инструкции по разделам.
- Доля ответов «нужна помощь».

Правила показа:
- Число, меньше 3, не показывается; вместо него — «<3».
- Никаких разбивок «по людям», «по времени суток», «по порядку ответа», которые позволяют узнать автора.
- Свободный текст не выводится на дашборд. Координатор читает его отдельно, после очистки от имён и ссылок на личное.

## 7. Хранение и доступ
- Ответы хранятся в сервисе формы; экспорт в CSV — только на компьютер координатора, не в git.
- Сводка (агрегаты без текста) может попадать в `PROGRESS.md` или в `docs/team/`.
- Доступ к ответам — только координатор.
- Срок хранения: до конца этапа; затем удаление ответов и экспорта. Срок — решение команды.
- Удалить свой ответ нельзя: анонимный ответ невозможно найти. Это указано во вводной части формы, чтобы участник знал до заполнения.

## 8. Вводный текст формы (пример)
> Форма помогает нам понять, где проект трудно. Ответы анонимны: мы не собираем имя, e-mail и логин. Ответы не оцениваются. Цель — улучшить инструкции и помощь. Заполнение необязательно.

## 9. Что не делаем
- Не сравниваем участников между собой.
- Не привязываем трудности к оценке или зачёту.
- Не собираем данные по GitHub-активности для этой цели.
- Не публикуем свободный текст без очистки.

## 10. Открытые решения
1. Платформа формы: Google Forms или Microsoft Forms (и проверка настроек сбора e-mail).
2. Порог показа сводки (предложено: 3).
3. Срок хранения ответов.
4. Кто координатор и как часто смотрит сводку.
5. Канал, где публикуются ответы на частые вопросы (мессенджер или `docs/FAQ.md`).
