# Структура данных

| Папка | Содержимое | В git |
|---|---|---|
| `raw/<id>/` | Скачанные файлы как есть. `<id>` — из `config/sources.yaml` | нет |
| `processed/` | Очищенные таблицы для расчётов и дашбордов (CSV, UTF-8, разделитель `;`) | нет |
| `reference/` | Справочники: регионы, федеральные округа, ОКВЭД, профессии (небольшие CSV) | да |
| `references/<id>/` (во множественном числе, корень репо) | Опубликованные документы в оригинале (PDF, HTML, XLSX) и их CSV-извлечения. Только для чтения | да |

## Форматы
- **Сырые данные:** в исходном формате (XLSX, PDF, JSON, XML, SPSS). Не редактировать.
- **Обработанные данные:** CSV, одна таблица — один показатель в длинном формате: `дата; регион; показатель; значение; единица; источник`.
- **Даты:** `ГГГГ-ММ` для месячных рядов, `ГГГГ-КК` для квартальных.

## Разделители и десятичный знак
- `processed/` и все новые CSV-таблицы проекта: разделитель `;`, десятичный знак — точка (`1.5`), кодировка UTF-8.
- `raw/` и `references/`: исходные файлы не переписываются. Если исходный CSV использует другой разделитель или запятую, это фиксируется в README папки, а не меняется.
- Извлечения из PDF (визуальная транскрибация) — тот же формат: `;` и точка.

## Правило для сырых файлов
Новые данные (PDF, CSV и др.) всегда сохраняются в `references/<id>/` (оригинал + `README.txt`: адрес, дата скачивания) и в `raw/<id>/` как рабочая копия.
Рядом со скачанным файлом (или в `raw/<id>/README.txt`) записать: адрес, дату загрузки, название таблицы.
